# R5 experiments E1-E3: ROM-as-logic, memory from gates, ISA re-ranking   (2026-10-22/23)
Code: `r5/exp/{common,e1_rom,e1_real,e2_mem,e3_model}.py` (use r4/tools/netlist.py; every netlist below was checked against its specification by exhaustive or random simulation). Raw outputs: `e1_random.txt`, `e2_mem.txt`, `e3_model.txt`. Units = NAND + 6 DFF unless said otherwise. Labels: [M] measured here, [E] model/estimate.

## E1: cost of a ROM built as constant NAND logic [M]
Three constructions of the same address->word function (all verified):
- **plane** (two-level predecode, one NAND per word line, OR plane per output bit): the construction whose layout is a regular function of the contents, so a quine can regenerate it by reading itself.
- **shannon** (recursive Shannon expansion, structural hashing; a shared mux DAG): smaller, but the sharing is data-dependent, i.e. an irregular blob.

| data | ones density | plane NAND/word | plane NAND/1-bit | shannon NAND/1-bit |
|---|---|---|---|---|
| random, N = 256-1024 words, 8 bits | 0.10 / 0.25 / 0.50 | 3.9 / 5.2 / 8.3 (N=1024) | 3.0 / 2.5 / 2.0 | 2.0 / 1.2 / 0.66 |
| random, 16-bit words | 0.10 / 0.25 / 0.50 | 4.1 / 8.6 / 13.7 | 2.6 / 2.2 / 1.7 | 1.75 / 1.06 / 0.59 |
| real code (R3c ROM, first 2 KB) | 0.23 | 4.2 | 2.26 | 0.92 |
| real code (R4 ROM, first 4 KB) | 0.34 | 6.0 | 2.24 | 0.72 |
Findings:
1. **A self-derivable ROM plane costs ~2.2-2.3 NAND per stored 1-bit (4-6 NAND per byte of real code)** [M]. My design-note estimate of 1-2 per 1-bit was too low; it is corrected in `R5_DESIGN.md`.
2. The Shannon/DAG form is 2.5-3x cheaper for real data, **but it cannot be used inside a quine unless its sharing structure is itself cheap to describe**: an irregular DAG costs ~20-40 units per gate to describe (E3), more than it saves [E]. It is a lower bound for "ROM that needs no copying", not for R5.
3. Choosing the sparser polarity per column (+1 inverter) changes almost nothing on real code (< 3 %). Hamming-weight-minimizing encodings (E5) are the remaining lever: every 1-bit removed saves ~2.3 NAND.
4. Fixed decoder overhead is small once N >= 256 (1 NAND per word + predecode).

## E2: memory from gates [M]
| kind | N x W | NAND/bit | units/bit (NAND+6 DFF) | avg access ticks |
|---|---|---|---|---|
| addressable RAM (decode, hold mux, AND-OR read) | 8 x 8 ... 256 x 8 | 6.3-6.7 | **12.3-12.7** | 1 |
| word-parallel recirculating ring + counter + match | 8 x 8 | 0.84 | 7.1 | N/2 = 4 |
| same | 64 x 8 / 256 x 8 | 0.18 / 0.06 | 6.25 / 6.08 | 32 / 128 |
| bit-serial recirculating ring + counter + match | 64 x 8 / 256 x 8 | 0.21 / 0.06 | 6.3 / 6.1 | 256 / 1024 |
Findings:
1. The addressable-RAM figure reproduces the ISA study's calibration (12.3 units/bit) [M].
2. **Ring memory costs about half per bit (6.1-7.1)**; the saving is the removed decode and read mux. The floor is the DFF itself (6 units). Overhead (counter, comparator, write mux) is ~100-130 NAND, so below ~64 bits the ring is not worth it.
3. The price is access time (N/2 ticks for the word-parallel ring), and a program that must wait for its word. For the quine's ~100-bit state the saving is ~600 units; the access-time cost matters more than the gates there.
(Variants with N x W > 1024 bits were counted but not simulated.)

## E3: ISA re-ranking under the new price list [E: a model on measured pieces]
Model: an irregular gate (or DFF) costs itself plus the ROM-logic that describes it, `bits_per_gate / 8 * 5.5` units; program ROM 5.5 units/byte (E1); quine state 100 bits in a ring (6.5/bit). Description size per gate is the big unknown, so three values: 13 bits (xz of nandgen netlists, needs a decompressor), 26 (R4's module HD, measured), 55 (R3c's routed layout data per gate, measured).
| ISA (CPU only; Hack-vN, ACC8 measured, others estimates) | total @13 | @26 | @55 | description share @26 |
|---|---|---|---|---|
| Hack-vN (705 NAND/52 DFF) | 12.1k | **18.9k** | **34.0k** | 72 % |
| ACC8 (1203/62) | 15.1k | 26.4k | 51.6k | 86 % |
| 6502-lite (1190/76, est.) | 15.8k | 27.1k | 52.4k | 83 % |
| Z80-lite (1540/100, est.) | 18.6k | 33.3k | 66.0k | 88 % |
| SUBLEQ (750/80, est.; K1 only) | 10.6k | 18.0k | 34.6k | 82 % |
Findings:
1. **Describing the CPU to itself is 56-94 % of the total** [E]; code size is minor. Cost scales with irregular gates and with bits per gate, not with code density: each irregular gate removed saves ~10 / 19 / 39 units at 13 / 26 / 55 bits per gate.
2. Hack-vN stays first among the real netlists (the earlier ISA-study conclusion survives the new prices); SUBLEQ looks competitive only because its numbers are estimates and one kernel.
3. **The ranking is not the point; the multiplier is.** A design whose gates are mostly *regular* (bit slices, arrays, counters generated by loops) does not pay the per-gate description cost. The model above treats every gate as irregular, i.e. it is a worst case; a sliced 8-bit datapath with 8 identical slices pays for one slice. The next measurements therefore are (a) how many bits/gate a locality-ordered, layout-aware encoding really needs without a decompressor, and (b) how much of a CPU/sequencer can be made regular.
4. The proxy kernels (K1-K4) are not the quine program; the code term will change when the real program exists.

## Consequences for R5_DESIGN.md
- Section 3 price list: ROM 2.2-2.3 NAND per 1-bit (self-derivable plane); ring memory ~6-7 units/bit; addressable 12.3-12.7. Updated in the design note.
- Priority shifts from "pick the ISA" to "minimize irregular gates and bits per described gate". Proposed new experiments: **E6** description encoding (bits/gate for netlist+layout with locality order, no decompressor), **E7** regularity (bit-sliced and counter-based designs: gates described vs gates present), then E4 (quine skeleton) on the best candidate.
